## How the code fits together (read this first)

1. `config.py` defines `Settings`. pydantic-settings fills each field from an env var with the `LAB_` prefix (`LAB_DATA_ROOT` → `data_root`), or from a `.env` file, or falls back to the default.
2. `get_settings()` builds a fresh `Settings`. Everything that needs settings asks for it through this one function, which is what lets tests swap it out.
3. `api.py`: `GET /health` declares `settings: Settings = Depends(get_settings)`. FastAPI calls `get_settings()` for each request and passes the result in. Tests replace it with `app.dependency_overrides[get_settings] = ...`.
4. `cli.py`: `lab info` calls the same `get_settings()`, prints each expected source path with ok/MISSING, and exits 1 if any are missing. `lab serve` starts uvicorn on 127.0.0.1:8077.
5. `/health` returns HTTP 200 even when `degraded`. "Is the process up" (liveness) is separate from "is it ready to do real work" (readiness), so a missing data folder is a reported state, not a crash.

## Findings

| # | Severity | Where | Finding | Decision |
|---|---|---|---|---|
| 1 | **bug** | `config.py:13`, `tests/test_cli.py:8` | Settings read the developer's `.env`. With `LAB_DATA_ROOT` in `.env`, `monkeypatch.delenv` doesn't stop it being loaded, so `test_info_without_data_root_exits_zero` fails locally and passes in CI. Tests depend on the machine. | Fix: an autouse fixture that runs every test in an empty temp dir with all `LAB_*` vars cleared. |
| 2 | **bug** | `config.py:13,16` | `.env` and `warehouse_path` resolve against the *current directory*. Run `lab` from another folder and it silently ignores `.env` and would build the warehouse somewhere else. | Fix: resolve the relative `warehouse_path` to an absolute path when settings load, and show it in `lab info`. Document "run from the repo root" for `.env`. |
| 3 | design | `config.py:34`, `api.py:21` | `get_settings()` re-reads `.env` from disk on every request. Harmless now, wasteful once the API is called often, and settings could change mid-run. | Fix: `@lru_cache` it, and clear the cache in the test fixture. |
| 4 | tooling | `.pre-commit-config.yaml:3` | The pre-commit hook pins ruff **0.6.9**, but the venv and CI install **0.17.x**. The hook and CI could format code differently. | Fix: pin the hook to the same version. |
| 5 | tooling | `pyproject.toml` deps | Every dependency is `>=` with no lockfile, so CI can silently get different versions than the laptop (fastapi 0.165, starlette 1.10 today). | Fix: commit a `constraints.txt` (exact versions from the venv); CI installs with `-c constraints.txt`. |
| 6 | warning | `tests/` (TestClient) | `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated`. | Defer: track it; it's an upstream change. Filtered by exact message in pytest config so new warnings still show. |
| 7 | CI | `ci.yml:3-5` | Triggers on every `push` *and* `pull_request`, so a PR branch runs twice. | Fix: `push` to `main` only, plus `pull_request`. |
| 8 | test gap | `cli.py:21-24,37,41`; `api.py:28` | `lab serve` and the `warehouse_built=True` branch are never exercised. | Fix: test `warehouse_built` true; test the `serve` dispatch with uvicorn stubbed. `__main__` stays uncovered (fine). |
| 9 | note | `api.py:21` | `# noqa: B008` (function call in a default argument) is the standard FastAPI `Depends` pattern. Phase 1 can switch to `Annotated[Settings, Depends(get_settings)]`, which removes the noqa. | Fix now; it's one line. |
